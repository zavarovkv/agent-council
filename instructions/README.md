# Инструкции агентов

Здесь хранятся публичные примеры инструкций и навыков, которые поставляются с Agent Council.
Файлы можно читать и редактировать прямо в GitHub. Пароли, личные сведения,
идентификаторы пользователей и настройки подключений сюда не добавляются.

Личные инструкции можно хранить в отдельном закрытом репозитории и устанавливать
проверенным коммитом. См. [приватные инструкции](../docs/private-instructions.md).
В таком режиме рабочие правила редактируются в закрытом репозитории, а эти файлы
остаются примерами: обычное обновление Docker их поверх личных правил не копирует.

## Как применяются изменения

**Секретарь.** Правьте общие правила или текст ниже YAML-заголовка нужного
`SKILL.md`. Сохраните изменения в Git и разверните эту ревизию по
[инструкции](../docs/deployment.md). Docker включает файлы в образ; секретарь
читает их при запуске. Изменение файла только в GitHub не обновляет работающий
сервер. Имена ассистента и владельца подставляются из приватных настроек сервера.

Сценарий выбирает сервер по настройкам, описанным в
[руководстве секретаря](../docs/secretary.md#editing-reply-skills).
Смена стиля не даёт дополнительных прав. Текст инструкций не заменяет проверки
доступа, изоляцию контейнеров и запрет инструментов в коде.

**Личный ассистент и Dexter.** Эти файлы служат исходниками для
[явной установки профиля](../docs/deployment.md#dexter-jettster-internal-competitor-research).
Установщик сохраняет изменённые вручную инструкции: при конфликте останавливается
и просит согласовать версии. Обновление Docker само по себе не переписывает
существующие инструкции профиля. Перед заменой сохраните свои правки и резервную копию.

## Что остаётся снаружи

**Гостевые вызовы.** Общая публичная политика `guest/POLICY.md` входит в Docker-образ
и обновляется вместе с кодом. Приватные правила секретаря в этот сценарий не
подставляются, даже при вызове от владельца или жены. Включение и лимиты описаны
в [руководстве](../docs/telegram-guests.md).

Корневой [AGENTS.md](../AGENTS.md) содержит правила разработки репозитория и
остаётся на стандартном месте, где его находят инструменты разработки.

Личные и автоматически созданные навыки Hermes находятся в постоянном томе:
`/opt/data/skills/`, а навыки отдельных профилей —
`/opt/data/profiles/<profile>/skills/`. Там же остаются память, сессии и приватные
инструкции. Эти данные сохраняются резервным копированием, а не через Git.
Не переносите весь профиль в эту папку.
