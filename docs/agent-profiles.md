# Профили агентов

Эти правила применяются к новым агентам и изменениям существующих профилей.
Имена и описания в интерфейсах задаются на русском. Канонические значения для
текущей команды находятся в `src/council_team/catalog.py`.

| Имя | Профиль Hermes | Ник Linear | Специализация |
| --- | --- | --- | --- |
| Квай-Гон Джинн | `default` | `qui-gon` | Личный ассистент, координация, выполнение и проверка задач |
| Декстер Джеттстер | `dexter` | `dexterjettster` | Продукты, конкуренты, рынок, цены и потребности клиентов |
| Лэндо Калриссиан | `lando` | `lando` | Продвижение, позиционирование, SEO, контент и рост |
| Падме Амидала | `padme` | `padme` | Русская редактура, вычитка, сайт и материалы для руководства |

Это целевые значения оформления; наличие строки не подтверждает подключение.
Готовность проверяется в работающей системе. Исторический ID Linear-исполнителя
Лэндо — `marketing`: он сохраняется в OAuth-маршрутах и состоянии интеграции.

В текущем развёртывании выбраны `gpt-6.1-sol` для Квай-Гона и Лэндо,
`gpt-6-astra` для Декстера и Падме; у всех `reasoning_effort: high`.
Применять выбор и к нативному профилю, и к отдельному исполнителю Linear.
Активная конфигурация и учётные данные находятся в Docker volumes и резервной
копии, вне Git; лендинг читает действующий выбор, а не эту документацию.

## Имена и описания

- Видимое имя — полное имя выбранного персонажа кириллицей, одинаковое в Hermes,
  Linear, Telegram и новых отчётах. Название роли хранится в описании.
- Новый технический ID — короткое имя персонажа строчными латинскими буквами,
  при необходимости с дефисом. ID выбирается один раз; специализация может меняться.
- Ник Linear должен быть непустым и читаемым. После сохранения проверить реальный
  профиль, его URL и наличие агента в меню упоминаний. Правка может требовать
  учётной записи администратора; агентская OAuth-установка таких прав не даёт.
- Описание — одно-два предложения на русском: ответственность, основные навыки
  и ожидаемый результат. Оно должно соответствовать реально доступным инструментам.

## Аватарки

Использовать текущие портреты в `assets/agents/` как визуальные референсы.
Для нового агента генерировать оригинальную иллюстрацию выбранного персонажа:
выразительный портрет по плечи, единый рисованный стиль, чёткий силуэт и цветной
футуристический город на фоне. Как у нынешней команды, в руке — комлинк.
Лицо держать в центре с запасом под круглый кроп. Без текста, рамок и логотипов.
Проверять читаемость при размере 32–48 px и на светлом и тёмном фоне.

Для интерфейсов сохранять квадратный PNG 256×256 в `assets/agents/`.
Полноразмерный оригинал PNG или WebP хранить в `assets/agents/source/`, промпт и
сведения о референсах — в `assets/agents/<id>.md`. В Docker входят только портреты
для интерфейсов. Один согласованный портрет использовать во всех подключённых
интерфейсах. Замена готового портрета требуется только по отдельной просьбе.

Пример промпта: «[Персонаж], портрет по плечи в стиле приложенных аватарок Agent
Council. [Черты характера и специализация]. Выразительная рисованная иллюстрация,
единая манера линий и света, комлинк в руке, [цвет] футуристический город на фоне,
центральная композиция с запасом под
круглую обрезку. Квадрат, без текста, рамок и логотипов».

## Создание и проверка

1. Определить роль, имя, описание, технический ID и необходимые инструменты.
   Существующие навыки другого агента использовать, когда они подходят задаче.
2. Создать нативный профиль через API/CLI Hermes, настроить описание, модель,
   рабочую директорию и маршрут координатора. Новому специалисту по умолчанию
   не назначаются проект, пилот, кампания или расписание.
3. Хранить канонические инструкции в `<id>/SOUL.md` и `<id>/skills/` закрытого
   репозитория. Для изолированного Linear-исполнителя подключать общие навыки
   через `skills-source.json`, сохраняя его собственный контекст выполнения.
4. Если нужен агент в Linear, подготовить отдельное приложение и изолированный
   исполнитель, затем проверить установку, модель, упоминания и делегирование.
   Нативный профиль сам по себе не создаёт участника Linear.
5. Проверить копию профиля перед применением, сохранить данные и существующие
   подключения, выполнить проверки проекта и контролируемое развёртывание.
   Проверить имена, описания и аватарки в интерфейсах, обновить каталог и навык
   распределения задач, сделать резервную копию.

Текст навыков может быть общим; память, сессии и доступы разных контуров остаются
разделёнными. Секреты вводятся интерактивно и хранятся вне Git. Контейнеру агента
не передаются Docker socket, серверный ключ GitHub и права обслуживания хоста.
Если для подключения нужен ответ владельца, указать конкретный недостающий шаг
и выполненную часть работы. Подготовленные инструкции не равны готовому подключению.

## Обязательная редактура

Квай-Гон включает проверку Падме в критерии готовности результата с текстом для
сайта, публичной публикации или топ-менеджеров. Последовательность при необходимости:
исследование Декстера → черновик Лэндо → редактура Падме → итоговая сдача.
Редактор проверяет актуальную версию навыками русского языка, естественной стилистики
и целевого формата. Существенные замечания разрешаются до завершения; изменение
смысла, фактов или структуры после проверки требует повторной проверки изменённой части.
Готовность текста, подтверждение исходных данных и фактическая публикация фиксируются отдельно.

Для всех агентов Linear задавайте общие правила кратких комментариев: вывод и до четырёх пунктов, обычно до 700 символов; полный материал — в связанном документе. Доступ объединяет задачи и материалы текущего проекта или дерева под общим родителем. При добавлении роли синхронизируйте её приватные инструкции и публичный шаблон, не перенося личные данные в шаблон.

Все четыре агента получают общий инструмент `council_workspace` в нативных профилях
и в Linear. Он использует существующие подключения владельца к CouncilBase и папке
Drive без копирования OAuth-ключей. Новую роль добавлять явно в реестр разрешенных
клиентов и проверять доступ после установки; секретарь в этот реестр не входит.
Полный текст сдавать оформленной страницей Notion, в Linear оставлять ссылку.
Агенты переводят задачу в In Progress для работы и исправлений, в In Review для
приемки. В Done переводит только владелец. Редактор использует е/Е вместо ё/Ё
в готовых текстах и ответах, сохраняя код, URL и технические идентификаторы.
